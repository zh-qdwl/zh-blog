# 首页整屏 Hero 改造

日期：2026-08-13
起因：对照 liuyuyang.net，首页横幅的"背景格式"差距过大。

## 差在哪

差的不是配色，是首屏范式：

| | 参考站 | 改造前 |
|---|---|---|
| 尺寸 | 通栏 100vw × 满屏 | 1200px 容器内的圆角卡片，240–400px 高 |
| 底 | 摄影图 + 暗蒙版 | 纯 CSS 天蓝渐变 + 网格纹理 |
| 导航 | 透明浮在图上，白字 | 实心磨砂条，独占 60px |
| 内容 | 一句居中打字机文案 | 头像 + 站名 + 描述 + 统计 + 社交，左对齐 |
| 首屏 | 文章列表在第二屏 | 文章列表紧贴横幅下方 |

## 定下的方案

1. **整屏沉浸式**：Hero 通栏 100vw、高 100svh，导航透明浮在图上
2. **底图用户自备**，`HERO_IMAGE` 常量指向 `public/`，随时可换
3. **Hero 上只留打字机文案 + 向下箭头**；头像/统计/社交交给侧栏 ProfileCard 与页脚。
   站名最初也在整屏上居中显示，后改为不可见——但保留为 `.sr-only` 的 `<h1>`：
   直接删掉的话首页一个 `h1` 都不剩（`.section-title` 是 `<p>`，文章卡是 `<h3>`），
   标题层级断裂，读屏用户也失去"这是哪个站"的第一句话
6. **左上角品牌名与文档站名分开**：`SITE_BRAND`（左上角显示，当前 `HOWARD`）
   只影响视觉；`SITE_TITLE`（当前 `ZH 的博客`）继续用于标签页标题、RSS 源名、og:title。
   想全站统一，把两者改成同一个值即可
4. **导航首页透明白字，滚过 Hero 变实心**；其他页面完全不变
5. **「归档」进顶部导航**——旧 Hero 的三个统计数字是 `/archive` 全站唯一入口，去掉后必须补

## 实现要点

### Hero 移出 `.page`

`.page` 有 `max-width:1200px`，留在里面就得靠负 margin 破格。直接把 `<slot name="hero" />`
提到 `.page` 外面，`main.has-hero` 的 `padding-top` 归零、顶部留白改由下方 `.page` 的
`margin-top` 承担。`hasHero` 由 `Astro.slots.has('hero')` 判定，页面不需要显式声明。

### 导航用 fixed 而非 sticky

sticky 会在文档流里实打实占掉 60px，图顶就会被切出一条实心边。fixed 不占位。
样式全部写成 `.is-overlay:not(.is-solid)`，而不是"先覆盖成白字、再覆盖回默认" ——
滚过 Hero 后只要摘掉一个类，就自动落回原本的实心样式，两套样式不会互相追赶。

### 遮罩是对比度的合同

底图随时可换，所以**"当前这张图够暗"不能作为对比度依据**。唯一在换图后仍然成立的
保证是遮罩自己。

配色有两套，由 `consts.ts` 的 `HERO_TONE` 选择，`BaseLayout` 写成 `<html data-hero-tone>`：

| `HERO_TONE` | 适用底图 | 文字 | 遮罩 | 最坏底图 |
|---|---|---|---|---|
| `'dark'` | 暗色 | 白字 `#ffffff` | `rgba(6,12,24,.66)` | **纯白**（合成后最亮） |
| `'light'` | 浅色 | 深字 `#14181d` | `rgba(255,255,255,.68)` | **纯黑**（合成后最暗） |

（遮罩现在只覆盖顶部导航与底部箭头，不含中央文案——原因见下一节。）

**两套的最坏方向相反，这一点极易搞错**：白字压深色遮罩，怕的是底图太亮；
深字压浅色遮罩，怕的是底图太暗。写反了测试就变成一张永远通过的空头支票。
`tokens.test.ts` 按各自的最坏情况分别断言，并额外查两套令牌成对声明——
缺一项会在切换 `HERO_TONE` 时静默沿用另一套的值。

浅色那套的 α=0.68 是按"叠在纯黑上"反推的：卡通线稿类底图满图黑色描边，
深字压上去才是真正的最坏。合成后 `rgb(173,173,173)`，对 `--hero-ink` 7.9:1、
对 `--hero-ink-soft` 5.1:1。用当前底图的真实像素复核，文案区最暗的那个像素
合成后正好也是 `rgb(173,173,173)`——理论最坏值不是保守估计，是真会发生。

透明导航上的 hover 底纹与图标描边同样走 `--hero-veil-*` 令牌。写死
`rgba(255,255,255,…)` 的话，深字那套会变成白底纹压深字，hover 态直接糊掉。
Hero 加载中的兜底底色 `--hero-fallback` 也必须跟文字同向，否则首帧读不出字。

`.hero-scrim` 叠两条边带：

| 层 | 罩谁 |
|---|---|
| 顶部实心带（0→72px） | 透明导航（高 61px） |
| 底部实心带（0→72px） | 向下箭头 |

### 中央那层椭圆为什么被拿掉了

原本还有第三层椭圆罩着打字机文案。换上浅色平涂底图后，它在画面正中洗出一块
**边界分明的亮斑**——深色摄影图上完全看不见的东西，在平涂色块上一眼就能看出来。
按要求去掉。

去掉后实测：文案覆盖区约 **32%** 的像素对 `--hero-ink` 低于 4.5:1（黑色描边与深色衣物），
字确实读不清。导航带则是 0.0%，本来就不需要遮罩，边带留着是为了换图后仍成立。

### 文案改用「每个字自带描边」

整块遮罩会在平涂底图上糊出方块，而**描边贴着字形走，不会**。做法是 9 层 `text-shadow`：

```css
text-shadow:
  1px 0 0 var(--hero-halo), -1px 0 0 var(--hero-halo), /* …八个方向，0 模糊 */
  0 0 14px var(--hero-halo);                           /* 柔化外缘 */
```

前 8 条是 0 模糊的实色偏移，叠起来就是一圈**不透明**描边。这一点很关键：
描边不透明，字形边缘拿到的底色就恒等于 `--hero-halo`，与 `--hero-ink` 的对比度
**可以断言**（当前 17.8:1），而不是又一处"浏览器合成出来、令牌系统看不见"的颜色
——那正是 `polish-todo.md` D1 栽过的跟头。最后一条 14px 模糊只负责让它像光晕而非贴纸，
不承担对比度职责。

配合字号 20px → 33.6px、字重 300 → 500、字距 0.14em。
**"空灵"不能靠把颜色调淡或笔画调细实现**——两者都直接削可读性。
同理，原本的 `--hero-ink-soft`（更淡的副文案色）已删除，Hero 只保留最深的 `--hero-ink`。

### 两条教训

1. **遮罩这类"看不见的兜底"，可见程度取决于底图的性质而非亮度。**
   深色摄影图上 α=0.66 的遮罩毫无痕迹；浅色平涂图上 α=0.68 的遮罩就是一块补丁。
   换图要重估的不只是 `HERO_TONE`，还有遮罩本身该不该存在。
2. **被否掉的方案要往"能不能重新变得可测"的方向找替代，而不是退回到不可测。**
   中央遮罩去掉后，第一版只是把字调大调细，可读性变成了纯靠底图碰运气。
   换成实色描边后，保证重新落回令牌与测试上。

每层都是"先走一段实心、再开始渐隐"。若直接从 α 渐隐到 0，文字所在位置拿到的是
**衰减后的 α**，上面那条保证就不成立了 —— 这正是 `polish-todo.md` D1 那条教训
（`opacity` 衰减后的合成色，令牌系统与对比度测试都看不见）在图片背景上的翻版。

对应测试写在 `tokens.test.ts`，按"最坏情况 = 纯白底图"断言。

### 打字机

首句由服务端渲染进 HTML，脚本只负责"删掉再打下一句"的循环 —— 无 JS、爬虫抓取、
首帧渲染都能看到文案。`prefers-reduced-motion: reduce` 时脚本直接不启动，静态停在首句。

## 实测中发现并修掉的两个问题

### 1. 首屏一进来导航就错误地是实心态

原写法是"脚本执行时同步一次 + 监听 resize"。但脚本跑起来时 Hero 的样式未必已经落地
（dev 下组件样式由 JS 注入），那一刻 `hero.offsetHeight` 还不是整屏高度，
`hero.offsetHeight - header.offsetHeight` 算出来是负数，于是 `scrollY > 负数` 恒真。

改用 `ResizeObserver` 观察 Hero：开始观察时立即触发一次，之后高度每次变化
（样式到位、转屏、地址栏收放导致 svh 变动）都会重算。时机问题被彻底绕开。

### 2. 窄屏文案只剩 5px 余量

375px 下 `.hero-type` 可用宽度 309px，而最长那句实测占 304px。用户以后把文案改长
一点就会折行，而折行会在打字过程中把整块文字顶动。窄屏改成按两行预留高度
（`min-height: 3.6em`），折行不再造成跳动；只有一行时多出的空白由 `.hero-body`
的居中对齐吸收。

## 验证

单测 80 条全绿（新增 6 条：遮罩最坏情况对比度、`HERO_TAGLINES` 非空无空串、
`HERO_IMAGE` 绝对路径、`HERO_FOCUS` 格式、`/archive` 有导航入口、导航 href 唯一）。

浏览器实测（**生产构建产物**，非 dev）：

| 项 | 桌面 1280×800 | 移动 375×812 |
|---|---|---|
| Hero 尺寸 | 800px = 满屏，通栏，top=0 | 715px = 88svh |
| 首屏导航 | 透明、白字、`position: fixed` | 同 |
| 阈值前后翻转 | 384px 透明 / 404px 实心（阈值 394） | — |
| 实心态 | `srgb 1 1 1 / .82` + `--border` + blur，与其他页面一致 | — |
| 文案落在遮罩满 α 区 | 350–474 ∈ 246–490 | 314–424 ∈ 217–440 |
| 箭头在底部实心带内 | 距底 64px ≤ 72 | 距底 26px |
| 横向溢出 | 无 | 无 |
| 暗色主题两态 | 透明/白字 → `--bg` 0.82 + 亮字 | — |

其他页面（`/blog`、`/archive`、`/about`）确认无 `is-overlay`、无 `has-hero`、无 Hero 元素。

按 `polish-todo.md` D2 的教训，以上全部断言的是**计算样式与几何位置**，
不是渲染出的 HTML 子串。

## 遗留

- 整屏大图成为首页 LCP 元素，比原先的纯 CSS 渐变慢。当前底图 `labixiaoxin2.webp`
  已压到 1920×1407 / 128KB。`hero.webp`（宇航员，282KB）与 `labixiaoxin.webp`（155KB）
  留在 `public/` 里但已无引用方，想彻底清掉可以删除。
- **竖屏横向裁掉 62%**：当前底图接近 4:3，放进 375×715 的竖屏后只剩中间约四成，
  五个人物只留下广志与小白。这是宽图进窄屏的固有代价，`object-position` 解决不了
  （主体横跨整幅画面）。真要修得用 `<picture>` 做艺术指导，为窄屏单独准备一张竖构图。
- 换图流程写在 `README.md` 的「换首页的整屏底图」一节，核心是**`HERO_TONE` 必须跟着改**。
- `HERO_TAGLINES` 的长度上限约两行，已写进 `consts.ts` 的注释。
- 导航从 5 项变 6 项，375px 下触发已有的横向滚动兜底。
